# 更换配置时自动备份与迁移历史

本文说明当前源码的历史处理流程。[下载客户端](https://github.com/jxb412/yunqiao.me/releases/latest) · [安装说明](../INSTALLATION.md) · [客户端配置指南](CLIENT-CONFIGURATION.md)

ChatGPT / Codex 的编程历史可能按客户端配置中的供应商标识分开显示。云桥将这些分组称为“供应商区域”，例如 `openai`、`yunqiao` 或你自己设置的标识。区域名称不是模型名称，也不是云桥供应商列表中的编号。

为兼容的 **ChatGPT / Codex 桌面客户端或 Codex CLI** 应用、重新应用配置，以及恢复原配置时，云桥会自动备份并衔接历史归属，无需再去历史页执行一次批量迁移。

## 应用新配置

1. 在 **客户端接入** 选择客户端、供应商和模型，点击 **预览配置**。
2. 核对实际配置目录，以及可修复、无需修改、原样保留和备份后跳过的数量。
3. 保存工作，完全退出共享这份配置的桌面客户端，包括托盘中的程序，并结束相关 CLI 会话。
4. 有历史时点击 **备份历史并应用配置**；没有历史时点击 **备份并应用配置**。如果提示仍有客户端运行，退出后点击 **已退出，重新应用**。
5. 完成后核对处理数量，展开 **查看历史备份位置**，然后重新打开客户端验证。

历史处理范围是本次配置目录内的**全部未归档、已归档和子任务会话**。云桥先备份全部会话文件及发现的历史索引数据库，包括无需修改的会话，再同步供应商归属与可确认的路径，最后保存配置。重复应用同一个供应商配置也会检查和备份已有历史；没有历史时不会生成空的历史备份批次。

只有索引、找不到本机会话原文件的记录，会随索引数据库完整备份并原样保留，不阻止配置应用；这类记录会单独显示数量，不计入已修复或会话文件备份数量。云桥不会删除这些索引，也不会猜测补建聊天内容。后续找回原文件后，可重新预览处理。

历史内容损坏、编码异常、索引重复、原文件缺少必要索引或路径无法确认时，云桥会备份原文件和数据库，跳过这些会话的修复，继续应用配置。原文件留在原处，备份另存一份；不会移动或删除历史来强行修复。跳过原因随备份保存，可在结果中查看。

索引结构无法识别、无法确认关联范围时，本次历史只备份、不改写，客户端配置仍可继续保存。修复不了的旧会话不必先处理完，也不会因此禁用应用按钮；是否能在原客户端继续读取，取决于原文件本身是否完整。

应用前仍需保存工作并退出客户端。若磁盘空间不足、文件无读取权限等原因导致备份没有完成，云桥会说明实际失败原因，处理后可重试；不会把未完成的备份报告为成功。配置应用不会自动终止正在执行的 CLI 或桌面任务。

## 恢复原配置

在客户端卡片选择 **恢复 → 恢复原配置**，同样先保存工作并退出相关客户端。云桥先备份当前历史，再将当前会话衔接到原配置使用的供应商区域，然后恢复客户端配置。

这会保留当前会话正文和之后新建的会话，不会把历史整体倒退到首次接入时的内容。只想撤销高级执行权限时，使用 **恢复原执行权限**；该操作保留供应商连接。

## 备份、失败与中断

配置应用结果会显示实际备份的会话文件数和索引数据库数，以及已修复、无需修改、原样保留、备份后跳过的记录数和历史备份位置。跳过的会话不计入已修复；只有索引的记录在数据库备份中，不会显示为已备份的会话文件。备份保存在本机；配置备份可能包含 API Key，应与原配置一样妥善保管。

历史迁移或配置提交失败时，云桥会尝试撤销本批次历史和配置修改，再报告失败。若发现其他程序已修改会话、索引、配置或供应商状态，云桥会保留当前内容和备份，提示恢复冲突。不要为了重试而删除原历史或备份。

程序意外退出后，下次打开配置预览或应用配置会检查未完成批次。客户端已退出、内容仍能与本次操作对应时，云桥自动恢复该批次，再继续配置。有外部修改或无法确认的内容时停止恢复并提示处理；不会覆盖后来新增的对话来强行完成切换。

需要单独撤销某次历史迁移时，进入 **历史会话 → 批量修复历史 / 区域迁移 → 修复备份与恢复**，选择批次并 **预览恢复**。这个入口恢复历史修改；切回客户端原配置应使用客户端卡片上的 **恢复原配置**。

## 哪些内容会保留

迁移修改的是会话供应商归属和能确认的路径，不会更改会话 ID、聊天正文、归档状态、父子任务关系或原客户端登录文件，也不会把会话文件搬到另一个目录。

处理范围限于当前选择的 Codex 配置与历史目录。其他 `CODEX_HOME` 目录、远程电脑、Claude 历史和云端聊天不会被一起迁移；请先在预览中核对实际路径。

加密字段会保持原样。**迁移归属不会转换原账号或原供应商的加密身份，也不保证旧会话能跨账号、跨服务继续使用全部上下文。** 能否续聊取决于原客户端和模型服务；遇到身份不兼容时，可保留旧会话供阅读，并在新服务下新建会话。

## 独立整理指定区域或会话

应用配置时会自动处理全部历史。只需整理特定区域或会话时，可使用独立入口：

1. 进入 **历史会话 → 批量修复历史 / 区域迁移 → 供应商区域迁移**。
2. 选择来源和目标区域，按需限定未归档、已归档或全部历史。
3. 点击 **扫描并预览**，查看每条会话的修改原因，勾选可处理的会话。
4. 退出相关客户端并确认，再点击 **备份并迁移所选**。
5. 重新打开使用目标区域的客户端查看结果。

目标区域以当前实际配置为准；旧区域即使不再用于连接，也可能继续出现在来源列表。独立手动迁移按页面可处理的范围执行，遇到缺失、重复、路径歧义或不支持的子任务记录时会说明原因。配置自动衔接会统一备份全部主会话和子任务，能修复的修复，不能修复的原样保留并记录原因，继续保存客户端配置。
