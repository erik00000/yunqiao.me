# 配置与日常管理改进

## 已实现

| 场景 | 改进 |
| --- | --- |
| 配置已保存，实际使用仍有问题 | 客户端卡片和配置完成页增加“连接诊断”。检查安装能力、配置位置和格式、所选模型与凭据、网关、官方登录记录、共存模型目录、备份及外部修改，并比较当前端口／令牌与受管理配置。 |
| Windows 商店版 Claude 读取了另一套配置 | 配置写入、自动发现供应商共用目录解析器，识别普通版及 MSIX 的独立目录。多个目录并存时明确提示歧义；恢复始终绑定首次接入的原目录。macOS 使用 Application Support 原生目录。 |
| 供应商、账号和额度太多 | 卡片／紧凑列表可切换并记住偏好；搜索可结合协议、启用状态、余额状态筛选。多 Key 详情折叠，刷新、同步、编辑和测试入口保留。 |
| 子代理日志淹没主会话 | 默认显示主会话，可切换子代理和全部会话，并显示数量、定位所属会话。依据原生元数据和标准目录识别，普通分支和未知格式不会被误藏。 |

连接诊断只读本机文件，不调用模型、不写入配置、不生成或刷新登录凭据。可复制的报告不含密钥、账号、供应商自定义名称或个人路径。配置检查通过不等于运行中的客户端已加载，也不证明上游连通或额度有效；重启与手动连接测试仍是独立操作。

余额筛选描述各条查询结果：失败、未知、存在零或负余额、暂停查询。不会跨币种或跨额度项目相加，也不会因为一个 Key 余额为零就判定整个供应商不可用。旧结果明确标记，不能当作当前零余额。

会话分类不修改历史文件。父会话缺失或存在重复 ID 时保留阅读并提示原因，不随机跳转；子代理不会生成可能恢复到错误会话的命令。读取和扫描均防止旧响应覆盖新选择，嵌套弹窗仅由最上层响应 Esc 和 Tab。

## 验证

核心回归由 `node scripts/test-core-all.mjs` 统一运行，新增目录识别、诊断、会话关联专项。Windows/macOS 持续集成均接入新增界面检查：

- `scripts/test-client-diagnostics-ui.py`
- `scripts/test-provider-views-ui.py`
- `scripts/test-session-relations-ui.py`

测试使用隔离配置与模拟服务，不修改真实客户端、不关闭用户程序、不消耗模型额度。平台验收结果记录在 [WORKFLOW-VALIDATION.json](WORKFLOW-VALIDATION.json)。

## 后续候选

Windows／WSL 多实例独立配置、历史全文检索与扫描错误区分、每次请求重试链路、首次有效输出与生成速度、逐模型能力声明值得继续做。它们需要新增明确的数据边界与验收，当前版本未宣称支持。跨设备配置同步需要凭据加密、冲突处理和可恢复流程；不应简单上传整份配置。
