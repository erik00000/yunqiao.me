# 目录和更新链路补查

本轮限定检查设置隐藏后的旧配置兼容、启动目录缓存/刷新和客户端更新来源。没有修改 PHP 服务端、会员账本或线上发布状态。

已有链路：设置页隐藏目录地址、同步开关和更新源；旧设置读取、保存及导入均保持自动模型同步开启，更新源统一为 GitHub。启动目录请求由所有界面共享；有缓存时立即显示并后台刷新，首次没有缓存时等待本轮请求；15 秒状态刷新会显示后台取得的新目录。目录刷新不覆盖用户已保存的供应商 URL、密钥、模型定价或主动清空的模型列表。

本次修复：

- 旧目录地址为空、损坏、含凭据或使用不支持的协议时，选择官方目录及对应缓存，避免 `new URL()` 异常使 `state.get` 失败。仍保留有效的既有自定义目录配置。
- 远端目录校验成功、仅缓存保存失败时继续返回本轮新目录，并明确提示缓存未保存；不再误报远端不可用或倒退到旧缓存。
- 无效重定向地址转为可捕获请求失败；响应中途断开及时使用已有有效缓存；连续小块数据不能无限续期，整个请求及重定向共用 12 秒截止时间。

验证结果：

- `node scripts/test-catalog-resilience.mjs`：9 项通过，使用本地 HTTP 测试服务及内存/临时缓存。
- `node scripts/test-management.mjs`：19 项通过，包含共享启动请求、缓存立即可用、网络失败保留缓存、切换地址时不混入旧响应、用户模型数据保留。
- `node scripts/test-updates.mjs`：21 项通过，更新主链路无需新改动。

客户端更新优先 GitHub `/releases/latest`，失败自动官网；手动官网备用必须不低于已显示版本。安装包按平台/架构验证，禁止降级和未签名 iOS ZIP。当前线上尚无 GitHub 正式版、官网 0.4.0，本地 0.6.0 因此不会显示升级下载。更新协议与线上状态详见 [UPDATE-CHECK-VALIDATION.md](UPDATE-CHECK-VALIDATION.md)。
