# 客户端配置目录与接入流程

ChatGPT 桌面入口通过 `config.toml` 配置客户端使用的接口地址、认证和模型。程序安装位置与配置目录分别识别；找不到 `.exe` 或 `.app` 不阻止配置预览和保存。

| 用途 | Windows | macOS |
| --- | --- | --- |
| Codex 共享配置 | `%USERPROFILE%\.codex\config.toml` | `~/.codex/config.toml` |
| 原客户端登录文件 | `%USERPROFILE%\.codex\auth.json` | `~/.codex/auth.json` |
| 自定义 Codex 配置目录 | 已设置 `CODEX_HOME` 时使用其中的 `config.toml` | 同左 |
| Claude Code 用户配置 | `%USERPROFILE%\.claude\settings.json`，遵循 `CLAUDE_CONFIG_DIR` | `~/.claude/settings.json`，遵循 `CLAUDE_CONFIG_DIR` |
| Gemini CLI | `%USERPROFILE%\.gemini\settings.json` 与 `.env` | `~/.gemini/settings.json` 与 `.env` |

向导显示本次实际使用的配置路径。Claude 桌面版另用系统对应的应用数据目录与 `Claude-3p/configLibrary`，不套用 Claude Code 路径；多目录有冲突时先确认位置。

## 配置流程

1. 选择客户端、供应商和模型。运行时发现的本地 API 配置会导入供应商列表；官方 OAuth 登录记录单独识别。
2. 在“共享编程配置”查看实际路径。已有文件会标为“已发现配置”，首次配置会标为“应用时创建”。
3. 选择接入方式，预览实际文件路径和脱敏差异，再点击“备份并应用配置”。预览不修改配置；应用时检查文件是否被其他程序修改，有冲突则要求重新预览。
4. 重启读取这份配置的客户端。需要云桥一键重启或桌面增强时，展开“程序识别”，重新检测或选择 Windows 主程序/macOS `.app`。选择程序不会自动应用配置；更换程序会断开已有增强连接。
5. 需要撤销时使用“恢复”。桌面入口和 CLI 共用同一份配置与首次备份，修改和恢复状态同步。

同一份配置可以由 Codex CLI 和读取 Codex 配置的桌面版本使用。重启后客户端根据选中的 `model_provider`，使用对应供应商表的 `base_url`、`experimental_bearer_token` 和模型发送请求。桌面版本识别与配置保存分开检查，尚未识别的版本不能仅凭保存成功认定已经完成运行验证。

## 接口地址与密钥如何生效

| 接入方式 | 写入客户端的地址和密钥 | 请求路径 |
| --- | --- | --- |
| 云桥网关 | 本机网关地址、云桥访问令牌 | 客户端 → 云桥 → 所选供应商；云桥向供应商发送该供应商的 API Key 和原始模型 ID |
| 供应商直连 | 供应商 API 地址、供应商 API Key | 客户端 → 供应商；不依赖云桥网关运行 |

默认使用云桥网关，可转换协议、记录用量并应用网关功能。直连要求客户端与供应商的协议一致，且客户端适配器能够表达所需参数。供应商设置了自定义请求头或代理等需要网关处理的选项时，应使用云桥网关。官方账号与第三方模型共存也使用网关。

普通 API 模式写入 `model_provider = "yunqiao"`，并更新 `[model_providers.yunqiao]` 下的地址、Bearer 密钥与 Responses 协议。已有活动 profile 中的同名供应商覆盖会同步更新；其他供应商和 profile 保留。若同名供应商存在不兼容的 `auth` 或 `aws` 认证配置，预览会说明冲突并停止应用。新版 CLI 单独的 `--profile` 配置文件仍可能覆盖用户级设置，应确认客户端实际启动参数。

旧版 `aurora` 配置继续兼容本地识别和插件模型目录；重新应用 API 配置时使用新标识 `yunqiao`，旧供应商表保留，恢复仍可回到首次接入前的原文件。历史归属不会随配置改名自动修改：原 `aurora` 区域的会话可在“历史会话 → 批量修复历史 / 区域迁移”中迁到 `yunqiao`，支持预览、备份和恢复。官方账号共存仍使用客户端内置的 `openai` 标识。

## 官方账号与 API 模式

普通 API 模式写入独立供应商及其 Bearer 令牌，不改写 `auth.json`。某些桌面版本可能因此暂时隐藏官方聊天或云功能；保留登录文件与保留界面中的官方身份呈现是不同的行为。

需要同时使用官方账号与第三方模型时，选择“保留官方账号并与第三方模型共存”。此模式需要有效的本机官方登录和模型目录；官方请求与第三方请求使用分开的认证。详情见 [官方账号共存](CODEX-COEXISTENCE.md)。

## 验证

回归测试使用独立临时目录，覆盖未安装桌面程序时的预览、应用、恢复、登录文件字节不变、`CODEX_HOME`、CLI/桌面状态同步和外部编辑冲突。原生应用包测试进一步验证真实界面与 IPC 的完整流程。测试不会修改个人客户端配置或发起付费模型请求。

`node scripts/test-coexist-native.mjs` 使用本机真实 Codex 可执行程序、临时配置和本地模拟接口；不下载客户端，也不使用真实账号密钥。2026-11-15 在 `codex-cli 0.169.0-alpha.11.1` 上验证：客户端不带模型、地址或密钥的命令行覆盖，直接读取云桥生成的 API 配置；网关模式和停止网关后的直连模式均请求到指定接口，使用供应商密钥、正确模型，并保留原登录文件。共存模式的官方与第三方请求分离也通过。该验证不代表所有桌面版本或远程供应商均已实测。
