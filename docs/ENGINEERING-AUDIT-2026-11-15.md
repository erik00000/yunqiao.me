## 使用流程与性能

- 设置只提交用户实际修改的字段，不覆盖后台刷新的端口、代理或令牌。
- 供应商、分组和接入向导在写入期间防止重复提交；失败保留草稿，成功创建后同步失败仍保留 ID，避免重试重复创建。
- 批量模型应用提交预览时的精确选择与版本；手机端丢弃更换模型后迟到的预览，切换供应商继续保留已有官方账号共存模式。
- 会员分组加载失败不保留过期可选项；供应商已添加但模型同步失败时明确提示并允许继续。
- 未配置价格（包括已使用却缺失的缓存价格）显示“价格未配置”，与已明确配置为零价格的免费模型区分。汇总仅计算已知价格请求并显示未计价数量，旧记录不猜测历史价格。
- 请求列表只倒序读取所需的近期日志；20,000 条测试日志获取最后 7 条仅读取 64 KB。损坏/不完整行被跳过，超长单行有 1 MB 上限，避免刷新时整周日志读入内存。
- 隐藏尚未执行自动清理的日志保留天数控件；未删除任何历史日志。其他页面部分读取失败时保留已成功加载的数据。
- 新增故障测试纳入 `npm test`；PHP 新增认证、HTTP、精选发布测试以及桌面关键界面/打包验收纳入后续 GitHub 构建流程。本轮没有触发线上构建或正式发布。

## 后续优先级

1. **发布前：建立真实客户端兼容矩阵。** 固定官方桌面/CLI 版本，覆盖安装、登录、官方与中转切换、插件启停、升级后恢复；新版独立 profile 文件的主动选择和自动发现仍需补齐。现有 CLI 模拟服务验证不能替代真实官方桌面在线会话。
2. **上线前：验收后台部署和恢复。** 本轮 PHP 修复尚未部署。需在 Linux PHP-FPM/Nginx 实际权限下验证备份恢复、会员唯一约束和站点配置，并建立账本缺失告警。账本与初始化标记一起丢失时无法自动区别全新部署。
3. **下一阶段：持久化与可恢复性。** 将应用配置提交、精选目录与审计逐步纳入事务存储和版本迁移；提供损坏配置的只读恢复页。现在已有冲突保护，但进程强制退出时跨文件提交仍可能不完整。
4. **用量增长后：统计索引与分页。** 最近请求已优化，长周期总计仍读取对应日期文件。可迁入 SQLite 增量汇总，配合可预览、可取消的归档清理；不要直接启用无确认的历史删除。
5. **功能扩展：先补实测能力。** 5 项原生增强、WorkBuddy 自动配置与普通 ChatGPT 聊天版第三方 API 接入仍存在明确边界。iOS 需要真机网络切换、后台恢复和签名分发验收；本轮没有生成新的 iOS 原生包。
